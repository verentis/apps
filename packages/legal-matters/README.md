# Legal Matters

An installable Canvas/file app for commercial advisory intake, a human conflict decision, agreed fees and a traceable draft in Invoicing. It holds no trust money. Access follows workspace and folder permissions: a matter's team field is informational, not an access list.

## Set up

1. Decide who may see matters. Everyone who can read `/legal-matters` (and the CRM, project, time, expense and invoice records a matter links) sees every matter there; use separate workspaces or folder permissions to keep teams apart.
2. Install Legal Matters and its dependencies: Canvas, Node.js, CRM, Project, Timesheets, Expenses, Invoicing and their dependencies (including Accounting). Set Accounting's base currency/precision and Invoicing's tax/due-day settings. Create the CRM and project records the matters will link. One dedicated project per matter avoids unintentionally selecting unrelated time.
3. The workflow runs on the main branch only; every write is conditional on the file's ETag.
4. Open Legal Matters → **Open intake folder in Files** → **New → Legal matter**. The script generates an opaque `MAT-<uuid>` under `/legal-matters`. The launch page lists every matter with its status; a matter opens beside the list.

## Intake and review

Enter the instruction, one client, any counterparties and related entities, and their semicolon-separated aliases. The client needs an active CRM company/contact path; other parties may also link CRM records. Record scope, fee terms and currency. Hourly work needs a linked active project and an employee/effective-date rate. An optional fixed fee is billable **once per matter**. Save, then **Screen**. The script compares exact normalised names/aliases and CRM links against the other matters (including declined and archived). It returns a count, not other files or their contents. It is not fuzzy matching, comprehensive external screening or a clearance.

A named human records clear, waiver-reviewed, or decline with reasons. Any matching matter requires waiver review or decline; re-screen if parties or the match fingerprint change. Opening freezes the reviewed engagement in the app. Team, document/task path references, manually verified dates and chronology are informational, not matter ACLs, generated deadlines or custody guarantees. Review names are self-reported, not authenticated signatures or proof of segregation of duties. Concurrent intake across the folder is not a transaction.

## Work in progress → invoice

1. In the opened matter, select sources by their exact workspace paths. Time must be **validated** against the same project; the script looks up the agreed employee rate effective on the work date. A **dedicated, single-line** approved/posted expense report is accepted only with a separate client-recoverability justification. Employee reimbursement alone never makes a billable charge. Do not allocate mixed or multi-client reports. Expenses do not have a native matter link; this assignment is a human decision.
2. Enter a deliberately client-safe line narrative, any positive partial write-down and its internal reason, then the pre-bill approver. No source narrative is copied. Save and **Prepare pre-bill**. Check the source, quantity, rate, write-down, released narrative, tax and net. Every amount uses exact-decimal/shared ledger arithmetic; a reduced line is billed as one adjusted amount while the internal record preserves original units and rate. Rejecting/discarding a preview allocates nothing. Currency conversion and fully written-off lines are not supported.
3. **Approve / resume draft**. The script checks source ETags, fee terms, settings and customer against the preview. It freezes the intent on the matter, reserves the whole batch (stable source IDs **and** paths) by one ETag-conditional update to `/legal-billing-register`, and creates `/invoices/LM-<batch-uuid>` with `If-None-Match: *`. Concurrent attempts cannot both acquire the same source through this workflow. A lost acknowledgement retries the same invoice ID/path without overwriting an existing draft. The final matter link opens the ordinary Invoicing record. Review address, tax, dates and amounts in Invoicing; **issue, credits, payment and posting remain there**. No trust receipts, deposits, advances, transfers or trust ledger.
4. If an operation conflicts or is interrupted, reopen the matter (refresh/reload following a failed script); use **Approve / resume draft** on its pending batch. Don't create a manual duplicate. If a source belongs to a different reservation, remove it from the next selection. Missing ETags, missing register and identity collisions stop progress. On an unresolved mismatch, stop and reconcile the register, matter chronology and invoice in the same workspace and branch. Do not delete reservations, regenerate the register, delete pending drafts or recycle source IDs. Before restore/reinstall, back up and restore matter files, register, referenced sources and invoices **together**.

The register is a retained seed, not an immutable audit log. It deliberately holds private snapshots to reconcile billing. It is a single optimistic-concurrency document, intended for small workspaces; other apps/manual invoices do not participate in its allocation protocol. There is no distributed transaction with source edits, anti-tamper protection from VFS writers, historical register reconstruction, or protection against manual deletion/replacement of these files. Never manually reset an abandoned reservation.

## Known limits

- Node's `NodePermissionGuard` / `FolderPermissions` implement secured-folder decisions; `VisibleFileListingHandler` filters child listings. The Node SDK transmits conditional writes and `PathWritePrecondition` enforces them. Execution resolves owning-app settings (`RequestExecutionCommandHandler.ResolveExecutionSettingsAsync`); the workflow compares the provisioned settings with `engine.context.workspace.id`, **not** a caller-supplied workspace ID. File-access declarations scope the app/script, not a specific matter team.
- This package does **not** provision or verify per-matter secured-folder grants, membership, or equivalent rules for separately stored CRM, project, time, expense, invoice, search, export and attachment surfaces. Files users and other authorised VFS writers can still bypass app validation. Revoking access means revoking workspace membership, folder permissions, tokens and shares; the app holds no access list of its own.
- Recommended before handling real client data: a platform-backed two-principal access test of list, direct metadata/content, search, related records, widget/script runs, attachment links, export and billing paths, for the team separation you rely on.

## Package checks

`node src/build.mjs` regenerates manifest, overlays, scripts, schema, templates and Canvas documents using `tools/file-apps`. `node src/build.mjs --check` checks drift. `node --test tests/*.test.mjs` exercises guarded actions, conflict disposition, money and source validation, concurrent reservations and interrupted writes using the shared ETag-aware memory file client. These are not live installation, end-user authorization or browser tests.
